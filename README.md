# Bobby Carrot — C++ / WebAssembly

Реализация оригинальной J2ME-головоломки **Bobby Carrot** (FDG Mobile Games, 2004) на C++20.
Собирается в две цели из одного исходника: нативный бинарник на SDL2 и WebAssembly через Emscripten.
Все 50 оригинальных уровней, оригинальные спрайты, тайлсет и музыка.

```
┌─ src/core/      чистая логика, ни строчки SDL — тестируется отдельно
├─ src/gfx/       SDL_Renderer + stb_image
├─ src/audio/     свой микшер поверх SDL audio + stb_vorbis
├─ src/platform/  ввод, сохранения, главный цикл, точка входа
└─ tests/         солвер, доказывающий проходимость всех уровней
```

---

## Быстрый старт

```bash
# 1. ассеты (не лежат в репозитории, см. «Лицензия на ассеты»)
tools/fetch_assets.sh

# 2. нативная сборка и запуск
make run

# 3. веб-сборка (нужен Emscripten, см. ниже) и локальный сервер
make web && make serve      # → http://localhost:8000/index.html
```

## 1. Ассеты

Графика, уровни и музыка в репозиторий **не включены** — это собственность FDG Entertainment.
Скрипт забирает их из публичных репозиториев-клонов в вашу рабочую копию:

```bash
tools/fetch_assets.sh                 # по умолчанию в assets/v1
tools/fetch_assets.sh /path/to/assets # или куда скажете
```

Должно получиться: **25 PNG, 50 `.blm`, 4 `.ogg`**. Скрипт сам это проверит.

Если у вас есть легально купленная копия — оригинальный `.jar` это обычный ZIP,
`unzip BobbyCarrot.jar -d assets/v1/` даст те же PNG и `.blm`.

Нужен только `git`. Любой путь можно потом передать игре через `--assets`.

---

## 2. Нативная сборка

Нужны: компилятор с C++20 (GCC 11+ / Clang 14+), CMake 3.21+, **SDL2**.

```bash
# Debian/Ubuntu
sudo apt install build-essential cmake libsdl2-dev
# Fedora
sudo dnf install gcc-c++ cmake SDL2-devel
# macOS
brew install cmake sdl2
# Arch
sudo pacman -S base-devel cmake sdl2
```

```bash
cmake -S . -B build-native -DCMAKE_BUILD_TYPE=Release
cmake --build build-native -j
./build-native/bobby
```

Больше ничего ставить не надо: PNG декодирует `stb_image`, Ogg — `stb_vorbis`, оба лежат в
`src/third_party/`. Ни `SDL2_image`, ни `SDL2_mixer` не нужны.

Если ассеты лежат не в `assets/v1`:

```bash
./build-native/bobby --assets /path/to/assets/v1
```

## 3. Веб-сборка (WebAssembly)

### Установка Emscripten

```bash
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install latest
./emsdk activate latest
source ./emsdk_env.sh          # делать в каждой новой сессии терминала
```

Нужны только `git` и `python3`. Первая сборка дополнительно скачает порт SDL2 — это нормально.

Как вариант, в Debian/Ubuntu есть пакет: `sudo apt install emscripten` (версия старее, но проект
собирается и ей — специально не используются API новее SDL 2.0.10 и Emscripten 1.38).

### Сборка

```bash
emcmake cmake -S . -B build-web -DCMAKE_BUILD_TYPE=Release
cmake --build build-web -j
```

На выходе в `build-web/`:

| файл | размер | что это |
|---|---|---|
| `index.html` | ~4 КБ | страница-оболочка из `web/shell.html` |
| `index.js`   | ~78 КБ | загрузчик и glue-код |
| `index.wasm` | ~48 КБ | собственно игра |
| `index.data` | ~750 КБ | упакованные ассеты |

### Запуск

Открывать `index.html` двойным кликом **не получится** — браузер запретит `fetch` по `file://`.
Нужен любой локальный сервер:

```bash
cd build-web && python3 -m http.server 8000
# → http://localhost:8000/index.html
```

Или `make serve`, что делает то же самое.

Для выкладывания на хостинг достаточно скопировать все четыре файла рядом. Отдавать их надо с
правильным MIME-типом для `.wasm` (`application/wasm`) — почти все статические хостинги
(GitHub Pages, Netlify, nginx) умеют это из коробки.

## 4. Управление

| | |
|---|---|
| Движение | `↑` `↓` `←` `→` или `WASD`, на тачскрине — свайп либо экранные стрелки |
| Рестарт уровня | `R` |
| Переключить вид | `F` — вся карта 512×512 ↔ оригинальный мобильный вьюпорт 320×384 со скроллом |
| Режим морковок/яиц | `T` |
| Звук | `M` |
| Меню уровней | `Esc` |
| Подтвердить | `Enter` / `Space` / тап |
| Следующий/предыдущий уровень | `N` / `P` (отладочное) |

Прогресс (открытые уровни, лучшее время, настройка звука) сохраняется: в браузере — в
`localStorage`, нативно — в файл `bobby_save.txt` рядом с бинарником.

## 5. Проверка правил

Семантика тайлов не документирована нигде — она восстановлена обратной разработкой.
Единственное убедительное доказательство её корректности: все оригинальные уровни должны
остаться проходимыми. Для этого есть солвер, который гоняет **настоящий** класс `Game`,
а не упрощённую модель:

```bash
./build-native/solve_levels assets/v1 8000000
# или
make test
```

Он делает поиск в глубину с отсечением по достижимости, а найденное решение потом
**переигрывает с нуля** на свежем экземпляре игры — чтобы победа не могла оказаться
артефактом поиска.

Этот тест уже окупился: он нашёл реальный баг. Проверка «всё ли собрано» у выхода
использовала счётчик, снятый до того, как засчитается последняя клетка травы, — а трава
засчитывается при **сходе** с неё, то есть ровно в том же переходе, который приводит на выход.
Из-за этого уровни режима «яйца» были непроходимы в принципе. См. комментарий в
`src/core/player.cpp::arrive`.

Текущий результат: **40 из 50 уровней решены, все 40 решений переиграны успешно**.
Оставшиеся десять (`normal22 23 29`, `egg05 06 07 12 15 16 17`) упираются в бюджет перебора,
а не доказывают непроходимость: режим травы по сути сводится к поиску гамильтонова пути,
и перебор там растёт экспоненциально. Солвер делает два прохода — сначала с глобальной
мемоизацией состояний (быстро, но неполно), затем только с защитой от циклов вдоль текущего
пути (медленнее, зато находит то, что первый проход пропускает).

## 6. Как устроено

### Формат уровня `.blm`

Ровно 260 байт, без сжатия:

```
0x00  4 байта   00 00 01 00  — u32 big-endian = 256, длина полезной части
0x04  256 байт  сетка 16×16, по байту на клетку, построчно
```

Один байт несёт сразу и графику, и логику: его значение — это индекс тайла в `tileset.png`
(`srcX = id % 8 * 32`, `srcY = id / 8 * 32`) и одновременно тип клетки. Полная таблица
семантики — в `src/core/tiles.hpp`, человекочитаемый дамп уровня:

```bash
tools/blm_dump.py assets/v1/level/normal01.blm
tools/blm_dump.py assets/v1/level/*.blm --summary
```

### Ключевые правила

- Проходимость проверяется **по обеим клеткам сразу**: поворот ограничивает не только вход,
  но и выход — на этом держатся все рельсовые головоломки.
- Повороты вращаются, рельсы переключаются, трещины обваливаются, трава приминается —
  всё это при **сходе** с клетки, не при входе.
- Примятая трава непроходима, поэтому уровни «яиц» — это поиск пути, проходящего через
  каждую клетку ровно один раз.
- Красный переключатель вращает все повороты на карте разом, жёлтый — разворачивает конвейеры.
- Смерть запускается, когда Бобби прошёл половину пути до дыры, а не когда дошёл.

### Фиксированный шаг

Логика крутится ровно на 60 Гц с аккумулятором, рендер — с частотой кадров дисплея.
Оригинал двигал Бобби на 2 пикселя за кадр, то есть 16 кадров на клетку; если привязаться
к `dt`, на 120-Гц мониторе игра поедет вдвое быстрее. Большой `dt` (вкладка была в фоне)
обрезается, чтобы симуляция не «перематывалась».

### Звук

Оригинальный саундтрек существует в виде MIDI и Yamaha SMAF (`.mmf`) — браузер не играет ни то,
ни другое. MIDI-треки взяты в виде Ogg-рендеров. Два эффекта, которые были только в SMAF
(подбор морковки и запертая дверь), синтезируются в рантайме коротким свипом — это десяток
строк вместо поддержки формата, который никто не мейнтейнит.

Браузеры не дают запустить звук до жеста пользователя, поэтому аудиоустройство
разблокируется на первом нажатии клавиши или тапе.

## 7. Что проверено, а что нет

Проверено в ходе разработки:

- нативная сборка GCC 13 / SDL2 2.30, без предупреждений;
- солвер: 40/50 уровней пройдены, все решения переиграны с нуля (см. раздел 5);
- рендер проверен покадрово на обоих видах — `--shot` снимает кадр оффскрином и пишет PNG,
  картинка сверена с оригиналом по тайлам, спрайтам, HUD и положению камеры;
- веб-сборка Emscripten 3.1.6 проходит до конца, получены `index.html/js/wasm/data`,
  модуль валиден (`WebAssembly.validate`), в нём присутствуют и SDL, и игровой код.

```bash
./build-native/bobby --shot normal 1 40 shot.png             # режим, уровень, тиков прогрева, файл
./build-native/bobby --handheld --shot normal 25 260 shot.png # то же в мобильном вьюпорте
```

**Не проверено:** реальный запуск в браузере, тач-ввод на телефоне и звук —
в окружении, где всё это собиралось, не было ни браузера, ни звуковой карты.
Если что-то не заведётся, первым делом смотрите консоль браузера.

Две оговорки по старому Emscripten (3.1.6 из пакетов Ubuntu), если возьмёте именно его:
линковка HTML падает в шаге `minify_html` на Python 3.13, и загрузка порта SDL2 может
споткнуться о контрольную сумму архива. На актуальном emsdk ни того, ни другого нет —
это ещё один довод ставить его из `emsdk`, а не из пакетов.

## 8. Лицензия

Код — делайте что хотите.

Ассеты — **нет**. Графика, уровни и музыка принадлежат FDG Entertainment, разрешения на
распространение нет ни у этого проекта, ни у репозиториев, откуда их забирает скрипт.
Для личного использования и изучения вопросов не возникает; публиковать сборку
с зашитыми ассетами не стоит.

Если захочется выложить играбельную версию — либо писать в FDG за разрешением, либо
нарисовать свой тайлсет: архитектура это позволяет, подменяется один файл `tileset.png`
плюс спрайты, формат уровней при этом не меняется.

## 9. Что дальше

- **Bobby Carrot 2 (Winterland)** — ассеты тоже есть, 30 уровней, тайлсет 8×8 вместо 8×6,
  кадры спрайтов 36×48 вместо 36×50. Нужны новые механики: снег разной глубины (тайлы 45–48),
  лазеры и ледяные блоки (49–52), телепорт (59). Таблицу тайлов для этого стоит вынести
  из `tiles.hpp` в конфиг, чтобы кампания подключалась данными, а не ветвлением в коде.
- Части 3–5 существуют только в iOS-сборках с другим форматом — их ассеты надо искать отдельно.
- Из мелочей: таблица рекордов по времени, экран паузы, перемотка хода назад
  (состояние уровня — 256 байт, откат делается тривиально).
