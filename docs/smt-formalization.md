# Проверка наличия выигрышной стратегии через SAT/SMT

Документ формально описывает задачу «есть ли у игрока выигрышная стратегия из
текущего состояния уровня» и алгоритм её решения на SAT/SMT-солвере.
Прототип: [tools/smt_solver.py](../tools/smt_solver.py).

Рассматривается базовый набор клеток из ТЗ: тропинка, трава, забор, морковка,
шипы, старт, выход. Ключи, конвейеры и поворотные камни не покрыты.

## 1. Состояние уровня

### Статика (карта, не меняется за игру)

| Обозначение | Смысл |
|---|---|
| `P` | проходимые клетки: тропинка, морковка, шипы, старт, выход |
| `K ⊆ P` | клетки с морковками |
| `S ⊆ P` | клетки с шипами |
| `fin ∈ P` | выход |
| `adj(c)` | соседи клетки `c` по четырём направлениям, лежащие в `P` |

Трава и забор для солвера неразличимы: их просто нет в `P`.

### Динамика

Состояние — тройка `(pos, got, dead)`:

1. `pos ∈ P` — позиция кролика;
2. `got ⊆ K` — собранные морковки;
3. `dead ⊆ S` — сработавшие шипы (кролик с них уже сошёл).

Больше в состояние ничего не входит:

- активность выхода выводится: выход активен ⇔ `got = K`;
- «кролик стоит на шипе» выводится из `pos`; шип попадает в `dead` в момент схода;
- старт после начала игры — обычная тропинка;
- число сделанных ходов на выигрышность не влияет.

### Переходы

Ход из `c` в `c' ∈ adj(c)` допустим, если `c' ∉ dead`. После хода:

- `pos := c'`;
- если `c ∈ S`, то `dead := dead ∪ {c}`;
- если `c' ∈ K`, то `got := got ∪ {c'}`.

Состояние выигрышное, если `pos = fin` и `got = K`.

### Выигрышная стратегия

Игра детерминированная и для одного игрока, поэтому стратегия — это
последовательность ходов. Выигрышная стратегия из состояния `s` существует ⇔
существует конечная цепочка допустимых ходов из `s` в выигрышное состояние.

Это сильнее, чем «путь из `current` в `finish`»: путь обязан собрать все
оставшиеся морковки и ни разу не зайти на сработавший шип.

### Соответствие движку

| ТЗ | Тайл движка ([tiles.hpp](../src/core/tiles.hpp)) |
|---|---|
| тропинка | `T_GROUND` (18), `T_CARROT_TAKEN` (20) |
| трава, забор | всё с id < 18 |
| морковка | `T_CARROT` (19) |
| шипы | `T_CRACKED` (30) |
| сработавшие шипы | `T_HOLE` (31) |
| старт | `T_START` (21) |
| выход | `T_EXIT` (44) |

Два отличия движка от текста ТЗ, оба на выигрышность не влияют:

- В движке зайти на `T_HOLE` можно, но кролик погибает. В модели сработавший
  шип — стена. Выигрышный путь в обоих случаях на такую клетку не заходит.
- По неактивному выходу в движке можно ходить как по тропинке. Модель это
  разрешает.

## 2. Постановка в SAT/SMT

Используется bounded model checking: игра разворачивается на `T` ходов, и
солвер ищет выигрышный путь длины не больше `T`. Все переменные булевы
(логика QF_BOOL, чистый SAT).

### Переменные, `t = 0..T`

| Переменная | Смысл |
|---|---|
| `at[t][c]`, `c ∈ P` | после `t` ходов кролик в клетке `c` |
| `got[t][k]`, `k ∈ K` | после `t` ходов морковка `k` собрана |
| `dead[t][s]`, `s ∈ S` | после `t` ходов шип `s` сработал |

Сокращение: `done[t] := at[t][fin] ∧ ⋀ₖ got[t][k]`.

### Ограничения

| # | Смысл | Формула |
|---|---|---|
| 1 | начальное состояние | `at[0]`, `got[0]`, `dead[0]` заданы текущим состоянием |
| 2 | кролик ровно в одной клетке | `exactly-one_c at[t][c]` |
| 3 | ход в соседнюю клетку | `at[t][c] → at[t+1][c] ∨ ⋁_{c' ∈ adj(c)} at[t+1][c']` |
| 4 | стоять можно только после победы | `at[t][c] ∧ at[t+1][c] → done[t]` |
| 5 | на сработавший шип нельзя | `at[t+1][s] → ¬dead[t][s]` |
| 6 | шип срабатывает при сходе | `dead[t+1][s] ↔ dead[t][s] ∨ (at[t][s] ∧ ¬at[t+1][s])` |
| 7 | сбор морковки | `got[t+1][k] ↔ got[t][k] ∨ at[t+1][k]` |
| 8 | цель | `done[T]` |

Ограничения 2–7 записываются для каждого `t`, 1 и 8 — по одному разу.

**Утверждение.** Формула `Φ(T)` выполнима ⇔ из текущего состояния существует
выигрышный путь длины не больше `T`. Путь читается из модели по `at[t]`.

Ограничение 4 разрешает «достоять» на выходе оставшиеся шаги, поэтому
выполнимость монотонна по `T`: если `Φ(T)` выполнима, то и `Φ(T+1)` тоже.

### Верхняя граница длины

Пара `(got, dead)` меняется только монотонно, не более `E = |K \ got| + |S \ dead|`
раз. Пока она не меняется, кратчайший путь не повторяет клетки. Значит, в
кратчайшем выигрышном пути не больше `(E + 1) · N` различных состояний, где
`N = |P \ dead|`, и

```
T_max = (E + 1) · N − 1
```

Если `Φ(T_max)` невыполнима, выигрышной стратегии нет. Следствие: задача лежит
в NP, свидетель — путь полиномиальной длины.

### Размер формулы

`O(T · |P|)` переменных и `O(T · |P|)` дизъюнктов (у клетки не больше четырёх
соседей). Для поля 16×16 и `T` порядка 100–200 это десятки тысяч переменных.

## 3. Алгоритм

```
has_winning_strategy(level, state):
    # предфильтр без солвера
    R = клетки, достижимые из pos в графе P \ dead
    если fin ∉ R или есть несобранная морковка вне R:
        вернуть НЕТ

    E     = |K \ got| + |S \ dead|
    T_max = (E + 1) · |P \ dead| − 1
    lo    = нижняя оценка длины пути
            # max по несобранным k: dist(pos, k) + dist(k, fin)

    # 1) удвоение: ищем первое T, при котором Φ(T) выполнима
    T = max(lo, 1)
    пока solve(Φ(T)) == UNSAT:
        если T == T_max: вернуть НЕТ
        lo = T + 1
        T  = min(2 · T, T_max)

    # 2) бинарный поиск кратчайшего решения на отрезке [lo, T]
    пока lo < T:
        m = (lo + T) / 2
        если solve(Φ(m)) == SAT: T = m
        иначе:                   lo = m + 1

    вернуть ДА, путь из модели Φ(T)
```

Шаг 2 нужен, только если требуется кратчайшее решение (эталонный маршрут,
подсказка «следующий ход», метрика сложности). Для ответа «да/нет» достаточно
шага 1.

Солвер используется инкрементально: развёртка только достраивается, а цель
`done[T]` передаётся как assumption. Выученные дизъюнкты переиспользуются между
вызовами.

## 4. Ускорение: сжатие карты до шипов

Кодировка из раздела 2 разворачивает игру по одному ходу, и формула растёт как
«длина пути × число клеток». Для ответа «нет» приходится доходить до `T_max`,
то есть до тысяч ходов. В игре используется более компактная постановка
([src/core/hint.cpp](../src/core/hint.cpp)).

**Наблюдение.** Необратимо меняют карту только шипы. По остальным клеткам
кролик ходит свободно, и состояние от этого не портится.

**Сжатый граф.**

- *Область* — связная компонента проходимых клеток без шипов. Внутри области
  кролик доходит до любой клетки и за одно посещение собирает все её морковки.
  Область можно посещать сколько угодно раз.
- *Шип* — одна клетка с живым шипом. Посещается не более одного раза.
- Ребро соединяет шип с областью или с другим шипом, если их клетки соседние.
  Две области напрямую не соседствуют: иначе это была бы одна область.

**Утверждение.** Уровень проходим из текущего состояния ⇔ в сжатом графе есть
маршрут от вершины кролика до области выхода, который проходит через каждую
область с несобранной морковкой и ни через один шип дважды.

**Граница.** Между двумя шипами в маршруте стоит не более одной области,
поэтому вершин в нём не больше `2·|S| + 1`. Достаточно одного вызова солвера с
горизонтом `H = 2·|S| + 1`; оставаться в области на месте разрешено, так что
более короткие маршруты тоже находятся.

**Переменные, `t = 0..H`:** `at[t][n]` — кролик в вершине `n`; `used[t][s]` —
шип `s` уже использован; `seen[t][r]` — область с морковкой `r` уже посещена.

**Ограничения:**

| Смысл | Формула |
|---|---|
| ровно одна вершина | `exactly-one_n at[t][n]` |
| переход по ребру, в области можно остаться | `at[t][n] → ⋁_{n' ∈ adj(n)} at[t+1][n']` (плюс `at[t+1][n]` для области) |
| шип используется один раз | `at[t+1][s] → ¬used[t][s]`, `used[t+1][s] ↔ used[t][s] ∨ at[t][s]` |
| область посещена | `seen[t+1][r] ↔ seen[t][r] ∨ at[t+1][r]` |
| цель | `at[H][область выхода] ∧ ⋀_r seen[H][r]` |

**Восстановление пути.** Маршрут по вершинам разворачивается в клетки обычным
поиском в ширину: в каждой области кролик сначала обходит её морковки (ближайшая
первой), затем идёт к клетке рядом со следующим шипом. Полученный путь
проигрывается по правилам из раздела 1, прежде чем попасть в ответ.

**Цена.** Путь получается не кратчайшим по числу ходов. Для подсказки это
допустимо; для метрики «минимальная длина пути» остаётся кодировка раздела 2.

## 5. Что не покрыто

- **Невырожденность уровня** (требование 4 ТЗ): «существует достижимое
  состояние, из которого выиграть нельзя». Это формула вида ∃∀, одним
  SAT-запросом она не выражается. Варианты: перебор состояний `(pos, маски)`
  или цикл «солвер предлагает префикс пути → `has_winning_strategy` из
  полученного состояния отвечает НЕТ».
- **Опциональные клетки**: ключи и замки добавляются как ещё одна монотонная
  компонента состояния. Конвейеры и поворотные камни требуют направления хода
  и немонотонного состояния клеток, граница `T_max` для них другая.
